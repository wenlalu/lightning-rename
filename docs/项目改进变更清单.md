─────────────────────────────            ─────────────────────────────

**理由**：主流个人开发者实践是"项目根 = 仓库根"。远程仓库（wenlalu/lightning-rename，main 分支）的实际树结构为根目录下的 `LightningRename\`、`tests\`、`docs\`、`build.ps1`、`README.md` 等。迁移后：
- `LightningRename.sln` 的相对引用 `LightningRename\LightningRename.csproj` 直接有效；
- `build.ps1` / `run_tests.ps1` 的 `..\` 相对路径全部恢复原设计语义（实测构建、测试一次通过）；
- 未来 `git add/commit/push` 无需再次搬动文件。

## 五、十项改进建议（按优先级）

**高**
1. **提交并推送本轮修复**：`git add -A && git commit -m "docs: 修正构建说明与忽略规则，补齐 editorconfig/gitattributes" && git push`。远程 README 目前仍与 build.ps1 行为不符，应尽快同步。
2. **一次性统一行尾**：仓库内行尾混杂（MainForm.cs 为 LF，其余多为 CRLF）。建议专门一次 commit 做规范化（`.gitattributes` 改为显式 `*.cs text` 等规则 + 全量重存），此后 diff 永久干净。当前为保逐字节一致暂用 `* -text` 冻结。
3. **v1.0.0 转正式版**：Pre-release 观察期已满（发布流程规范第三节），将 GitHub Release 标记为 Latest 并在页面公布 SHA-256。

**中**
4. **补充真实测试样本**：`tests\sample\` 现为 0 字节占位文件，放入小型真实文件使手工回归更可信。
5. **升级项目文件**：csproj 为 VS2010 旧式格式；可迁移 SDK 风格 csproj（仍面向 net40）或保持现状但增加构建脚本校验。
6. **拆分 Engine.cs**：19KB 单文件承担全部规则逻辑，按职责拆分（规则求值/冲突检测/事务执行）可提升可维护性（属下次迭代，不触碰当前冻结源码）。
7. **文档化版本策略**：语义化版本已在实践（CHANGELOG 规范良好），补一份 CONTRIBUTING.md 或版本策略说明。

**低**
8. **README 增强**：添加版本/平台/许可证徽章；本地化英文 README 面向国际用户。
9. **测试报告自动化**：`tests\测试报告.html` 为一次性手工产物，建议由 `run_tests.ps1` 自动生成或移入 docs 归档。
10. **发布归档规范**：`发布版\` 目前仅 exe；建议按版本建子目录并附 SHA-256 清单文件，形成完整发布档案。
